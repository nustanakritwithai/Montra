# MONTRA — บัญชีและเลือกอาชีพก่อนเข้าเกม

## การใช้งาน

- ผู้เล่นสมัครด้วยชื่อผู้ใช้ a–z, 0–9 หรือ `_` 3–24 ตัว และรหัสผ่าน 15–128 ตัว
- ตอนสมัคร ระบบแสดงรหัสกู้บัญชีหนึ่งครั้ง ให้ผู้เล่นเก็บเป็นความลับ หากลืมรหัสผ่านให้ใช้รหัสนี้ตั้งใหม่ แล้วเก็บรหัสกู้บัญชีชุดใหม่ รหัสเก่าและเซสชันเดิมจะถูกยกเลิก รุ่นนี้ยังไม่มีอีเมลกู้บัญชี
- ผู้เล่นเดิมนำรหัสกู้คืนตัวละครเดิม `mt1_...` มาผูกตอนสมัครได้ หากเบราว์เซอร์มีรหัสเดิมอยู่ หน้าสมัครจะใส่รหัสให้ ตรวจให้แน่ใจว่าเป็นบัญชีที่ต้องการผูก ทั้ง 3 ช่องจะผูกเข้าบัญชีเดียวกัน
- ตัวละครเดิมที่มีอาชีพอยู่แล้วใช้ต่อได้ ตัวละครที่ยังไม่มีอาชีพต้องเลือกก่อนเข้าโลก เมื่อเลือกแล้วเปลี่ยนเป็นอาชีพอื่นไม่ได้

## ข้อมูลและความปลอดภัย

บัญชีอยู่ใน `player-accounts.sqlite` ภายใน `MONTRA_CHARACTER_DIR` หรือโฟลเดอร์ข้อมูลตัวละครปกติ เก็บสำเนาฐานข้อมูลบัญชี **พร้อม** ตัวละคร เศรษฐกิจ และกิลด์ขณะเซิร์ฟเวอร์หยุด และเก็บสำเนานอกเครื่องด้วยตามแผนสำรองข้อมูลของผู้ดูแล ห้ามเปิดฐานข้อมูลทดสอบกับข้อมูลจริง

การผูกใช้รหัสอ้างอิงเดิมของแต่ละช่อง จึงไม่เปลี่ยน ID เงิน ไอเท็ม หรือตัวละคร รหัสกู้คืนเก่าหรือรหัสผ่านไม่ได้ถูกบันทึกเป็นข้อความตรง ๆ รหัสผ่านใช้ scrypt N=32768, r=8, p=3 พร้อม salt แยกต่อบัญชี ตามชุดทางเลือกใน [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) มีการจำกัดคำขอในหน่วยความจำสำหรับเซิร์ฟเวอร์กระบวนการเดียว การป้องกันนี้ไม่ใช่ระบบป้องกัน DDoS หรือระบบหลายเครื่อง

## ติดตั้งและเผยแพร่

เว็บใหม่นี้ต้องใช้เซิร์ฟเวอร์บัญชีรุ่นเดียวกัน อย่าเผยแพร่เว็บก่อนติดตั้งและเปิดเซิร์ฟเวอร์รุ่นใหม่ ตัวติดตั้งต้องหยุดเซิร์ฟเวอร์ก่อน จะสำรองโค้ด build และข้อมูลตัวละคร ตรวจสำเนา เพิ่ม route ใน `src/app.config.ts` แล้ว build โดยไม่เริ่มเซิร์ฟเวอร์เอง

เซิร์ฟเวอร์บังคับบัญชีโดยปริยาย `MONTRA_ACCOUNTS_REQUIRED=0` มีไว้ใช้กับเซิร์ฟเวอร์ทดสอบแยกเท่านั้น ห้ามตั้งค่านี้ในเซิร์ฟเวอร์จริง เพราะอนุญาตการเข้าแบบเดิม หลังอัปเดตให้ตรวจ `/montra/account/slots` โดยไม่ส่ง session: ต้องตอบ 401 แล้วจึงเผยแพร่เว็บรุ่นที่ตรงกัน

**การย้อนรุ่น:** โค้ดเซิร์ฟเวอร์เก่าไม่รู้จักบัญชี ห้ามย้อนเป็นรุ่นเก่าระหว่างผู้เล่นใช้งานบัญชีรุ่นใหม่โดยไม่มีแผนย้ายสิทธิ์กลับ และห้ามนำ snapshot ฐานข้อมูลเก่าทับฐานปัจจุบันโดยไม่ตรวจการเปลี่ยนแปลงหลังสำรอง เพราะอาจทำข้อมูลหาย
