# ระบบเงิน ตลาด และเทรด — ฝั่งเซิร์ฟเวอร์

เปิดใช้ด้วย `MONTRA_ECONOMY_ENABLED=1` ใน process MONTRA เท่านั้น ระบบใช้ Node.js ที่รองรับ `node:sqlite` (แนะนำ Node 24) และ SQLite แบบ WAL/`synchronous=FULL` ใน `MONTRA_CHARACTER_DIR/economy.sqlite` ใช้ได้กับ MONTRA **หนึ่ง process** เท่านั้น ไม่มีระบบ multi-node

ตัวละครถาวรได้รับเงินทดลอง 1,000 ครั้งแรกที่ย้ายเข้าฐานข้อมูล ยาและอาวุธนำจากเซฟเดิมโดยไม่แจกซ้ำ เงินและของฝากขายไม่ได้หมดอายุ ไม่มีภาษี ฝากขายหักของเข้าระบบก่อน ผู้ซื้อได้รับของและผู้ขายได้เงินในธุรกรรมเดียว หากกระเป๋าเต็ม เงินไม่พอ มีอาวุธชนิดนั้นแล้ว หรืออาวุธกำลังสวม จะปฏิเสธธุรกรรม การซื้อของตัวเองถูกปฏิเสธ

ตลาดแชร์ทั้ง process ระหว่างห้องและแผนที่ แต่ละตัวละครฝากขายพร้อมกันได้ไม่เกิน 20 รายการ และเห็นรายการของตนแม้รายการเก่าหลุดจากรายการล่าสุด เทรดโดยตรงต้องอยู่ห้องและแผนที่เดียวกัน ห่างไม่เกิน 5 หน่วย ทั้งคู่เสนอไอเท็มสูงสุด 1 ช่องและเงินได้อย่างอิสระ แล้วทั้งคู่กดยืนยัน เมื่อแก้ข้อเสนอจะล้างการยืนยันเดิม ข้อเสนอหมดอายุใน 60 วินาทีและยกเลิกเมื่อออกห้อง บนเซิร์ฟเวอร์ไม่เชื่อยอดเงินหรือไอเท็มที่ client อ้าง ไอเท็มที่เสนอถูกตรวจซ้ำก่อนโอน

เงินทดลองไม่มีแหล่งเพิ่มหลังแจกเริ่มต้น และยังไม่มีร้าน NPC, ค่าธรรมเนียม หรือการใช้เงินจริง ตัวเลขเหล่านี้ยังไม่ได้บาลานซ์ เปิดเมนู **ตลาด** บนเว็บเพื่อดูยอด ฝากขาย ซื้อ ยกเลิก หรือเลือกผู้เล่นใกล้ตัวเพื่อเทรด

## คำสั่ง Colyseus สำหรับผู้พัฒนา client

ต้องเชื่อมด้วยตัวละครถาวร ตรวจ `room.state.economyAvailable` แล้วส่ง payload ตามนี้:

- `get_economy {}` → `economy_state {gold}` และ `inventory_state`
- `market_list {}` → `market_state {listings:[{id,seller,item,price}]}` รายการของตัวเองและสูงสุด 100 รายการล่าสุด
- `market_create {requestId,slot,amount,price}` → `market_result` และสถานะกระเป๋า/เงิน
- `market_buy {requestId,listingId}` หรือ `market_cancel {requestId,listingId}` → `market_result` และสถานะกระเป๋า/เงิน ใช้ requestId สุ่มที่ไม่ซ้ำยาว 16–64 ตัวสำหรับแต่ละธุรกรรม หากส่งซ้ำด้วยข้อมูลเดิมจะได้ผลเดิม ไม่จ่ายหรือโอนซ้ำ
- `trade_request {targetId}` → `trade_update {tradeId,...}` ทั้งสองฝ่าย
- `trade_offer {tradeId,slot,amount,gold}` แต่ละฝ่ายเสนอของตัวเอง ใช้ `slot:null, amount:0` ถ้าไม่เสนอไอเท็ม `trade_update` แจ้งชนิด จำนวน และเงินของทั้งสองฝ่าย
- `trade_confirm {tradeId}` ทั้งสองฝ่ายต้องยืนยันหลังข้อเสนอล่าสุด เมื่อสำเร็จส่ง `trade_complete`, `inventory_state`, `economy_state`; `trade_cancel {tradeId}` ยกเลิกได้
- ข้อผิดพลาดส่งเป็น `economy_error {reason}` หรือ `command_rejected {reason}`; `character_busy` ให้รอธุรกรรมที่ค้าง การอ่านยอดเงินใหม่ของผู้ขายหลังขายสำเร็จทำได้ด้วย `get_economy`

## เซฟและการติดตั้ง

ก่อนเปิดครั้งแรก ให้หยุดเฉพาะ MONTRA และสำรอง `MONTRA_CHARACTER_DIR` ทั้งโฟลเดอร์เมื่อไม่มี process เขียน แล้วตรวจว่า backup ใช้อ่านได้ ค่อยติดตั้งและ build ด้วย `install-windows.ps1` และเปิดเซิร์ฟเวอร์ด้วย `NODE_ENV=production`, `PORT=4108`, `MONTRA_CHARACTER_DIR` ชี้ที่เดิม และ `MONTRA_ECONOMY_ENABLED=1` ไม่รันทดสอบบนข้อมูลจริง

เมื่อเปิด economy แล้ว SQLite เป็นแหล่งข้อมูลตัวละครและไอเท็มที่ถูกต้อง ไฟล์ `.json` เดิมเป็นเพียงสำเนาก่อนย้าย ห้ามนำมาใช้แทนเซฟปัจจุบัน การปิดแฟล็กบน build นี้จะปฏิเสธโหลดหากพบฐานข้อมูล และ **ห้ามย้อน build เก่าที่ไม่รู้จัก SQLite** เพราะอาจอ่านเซฟ JSON เก่าและทำให้ทรัพย์สินไม่ตรงกัน การสำรองฐานที่กำลังเปิดต้องใช้ SQLite backup ที่สอดคล้องกัน หรือหยุด MONTRA ก่อนคัดลอกทั้งไดเรกทอรีรวมไฟล์ WAL/SHM ไม่ควรคัดลอกเฉพาะ `.sqlite` ขณะมีการเขียน
