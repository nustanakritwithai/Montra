# หน้าช่างอาคม: ตีบวกและแปรรูปคุณภาพ

เปลี่ยนเฉพาะหน้าจอเว็บ ไม่เปลี่ยนกฎเซิร์ฟเวอร์ โปรโตคอล รูปแบบเซฟ ราคา หรือข้อมูลผู้เล่น

## ทางเข้าหน้าจอ

- คุยกับ NPC ช่างอาคม → เปิดโรงช่างอาคม → เลือก **ตีบวกอุปกรณ์** หรือ **แปรรูปคุณภาพ**
- ทั้งสองงานใช้หน้าต่างเฉพาะ ไม่แสดงปุ่มทำงานปะปนกัน และสลับงานได้โดยคงชิ้นที่เลือก
- แท็บอุปกรณ์ตัวละครแบบ paperdoll และกระเป๋าเหลือทางลัดไปหน้าช่างสำหรับชิ้นที่เลือก งานสร้างของเปิดหน้าสร้างของแยก ส่วนการ์ด แปรรูปทรัพยากรดิบ และแยกอุปกรณ์ยังใช้ทางเดิม
- ทางลัดภารกิจเปิดหน้าตีบวกพร้อมช่องเป้าหมายเดิม
- คลังช่างเป็นส่วนพับได้ เมื่ออุปกรณ์แตกและมีของสำรอง จะเปิดคลังรุ่นนั้นให้เบิก +0 ตามกฎเดิม
- ปุ่มกลับช่าง กลับกระเป๋า กลับเมนู ปิด และ Escape ใช้ระบบ drawer เดิม รวมถึงการคืนโฟกัสและปิดอินพุตสนาม

“แปรรูปคุณภาพ” ในหน้านี้หมายถึงการสุ่มออปชันเดิม (`reroll`) ไม่ใช่ระบบเปลี่ยนความหายากใหม่ ออปชันใหม่แทนที่ของเดิมและอาจได้ขั้นต่ำกว่าเดิม แต่ไม่เปลี่ยนรุ่น ความหายาก ขั้นตีบวก การ์ด หรือการผูกตัวละคร

## สัญญาระหว่างระบบที่ตรวจและคงไว้

| ส่วน | สัญญา |
| --- | --- |
| แหล่งสูตร | `MyRoomState.forgeCatalog` มาจาก `FORGE_CATALOG` ใน `ForgeRules.ts`; หน้าจออ่านราคา โอกาส สำเนาที่ใช้ ความเสี่ยง และเพดานจากข้อมูลเดิม |
| เป้าหมาย | อาวุธหลักรวมถึงชิ้นที่สวมใช้เลขช่องกระเป๋า 0–11; อุปกรณ์ร่างกายใช้ชื่อช่องจริง เช่น `leftRing` / `rightRing` |
| อุปกรณ์ที่สวม | ใช้ `wornGearAt` อ่าน `equipment`, `equipmentForges`, `equipmentSockets` ร่วมกัน เพื่อไม่ข้ามเงื่อนไขการ์ด |
| ตัวตนชิ้น | ส่ง `instanceId.revision` ผ่าน `gearStamp`; อุปกรณ์เก่าที่ยังไม่มี forge ใช้ `itemId` ตามเดิม เมื่อมี instance ครั้งแรกคงการเลือกไว้ แต่ถ้าเปลี่ยนเป็นอีก instance ให้เลือกใหม่ |
| ตีบวก | `forge_weapon` ส่ง `{slot, stamp, action:"enhance", requestId, copies, donor?, acceptBreak?, acceptDowngrade?}`; ยืนยันชื่อ ขั้น โอกาสลด/แตก สำเนา และทองก่อนส่ง |
| ชิ้นสละ | รุ่นเดียวกัน ไม่ใช่เป้าหมาย ไม่ใช่อาวุธที่สวม ไม่มีรูการ์ด (`socket === undefined`) ขั้นและ misses เป็น 0; ชิ้นที่ผูกหรือมีออปชันยังใช้ได้ตามกฎเดิม |
| สุ่มออปชัน | `forge_weapon` ส่ง `{slot, stamp, action:"reroll", requestId}` เท่านั้น ไม่มี copies / donor / การยอมรับความเสี่ยงของตีบวก; ใช้ตราตาม materialTier สำหรับอุปกรณ์ที่มี profile |
| ราคาและผล | ตัวคูณเลเวล การสุ่ม โอกาสสำเร็จ ลดขั้น แตก ระดับออปชัน และ pity ยังเป็นของเซิร์ฟเวอร์; โบนัสช่างเป็น PvE |
| เบิกคลัง | `claim_forge_copy` ส่ง `{gear, expectedStock, requestId}`; ยืนยันชิ้นผูก +0 และจำนวนคงเหลือ; เลือกชิ้นที่ได้จาก instanceId ในผลตอบกลับ ไม่เดาจากชื่อรุ่น |
| ความปลอดภัย | `EconomyRules.parseForge` / `parseClaimForgeCopy` และ `MyRoom.economyAction` ยังคุมรูปแบบคำขอ ตัวละครถาวร มีชีวิต อัตราคำขอ และงานบันทึก; ไม่เพิ่มข้อกำหนดระยะ NPC ที่เซิร์ฟเวอร์ไม่เคยมี |
| ธุรกรรม/เซฟ | `EconomyStore.once` และ `forgeWeapon` / `claimForgeCopy` คุมรายการซ้ำ ตรวจ stamp/stock หักของและทอง บันทึก SQLite แล้ว `syncEconomy` ส่งผล ไม่แก้เซฟหรือหักของในไคลเอนต์ |
| ผลล้มเหลว | อาวุธแตกทำช่องว่างและถอดอาวุธ; อุปกรณ์ร่างกายลบเฉพาะชิ้นและข้อมูล forge/socket ของช่องนั้น; หน้าจอไม่เลือกของคนละชิ้นแทนโดยอัตโนมัติ |
| การอัปเดต | inventory/economy/forge/claim/craft/card/error และการเปลี่ยนเลเวล/ชีวิต ใช้ `renderBag` ส่งต่อไป `renderForgePage` เมื่อเปิดหน้าช่าง; timeout และคำขอถูกปฏิเสธปลดสถานะรอและวาดใหม่ |
| การเชื่อมต่อ | เปลี่ยนห้องหรือออก LIVE ล้างการเลือกที่อาจเก่าและปิดปุ่ม; ไม่มีการส่งธุรกรรมซ้ำอัตโนมัติเมื่อ timeout |

## การตรวจเฉพาะงานนี้

- ใช้ Node ตาม `.nvmrc` แล้วรัน `npm run prepare:client` ที่ root ก่อนชุดตรวจ client นี้
- `node --check main.js`
- `node deploy/combat/forge-copy-ui-test.cjs`
- `node deploy/combat/forge-pages-ui-test.cjs`
- `node deploy/combat/service-npcs-ui-check.cjs`
- `node deploy/combat/item-hunt-ui-test.cjs`
- `node deploy/combat/salvage-ui-test.cjs`
- `deploy/combat/forge.test.ts`: 11 tests สำหรับกฎ forge/คลัง/ธุรกรรม/เซฟ โดยใช้ SQLite ชั่วคราวแยกจากข้อมูลจริง

เพิ่ม regression tests สำหรับหน้าที่แยก ปุ่มและข้อความแต่ละงาน เป้าหมายร่างกาย/การ์ด payload การกดซ้ำ ระหว่างรอผล เงินไม่พอ เลเวลไม่ถึง ตาย ชิ้นแตก/เปลี่ยน instance อุปกรณ์ legacy สูตรคราฟต์ และตัดการเชื่อมต่อ

`item-hunt-ui-test.cjs` เดิมขาด `itemHuntSource` ใน test context จึงเพิ่ม fixture stub และตรวจว่าทางลัดส่งช่องเดิมเข้า `openForgePage` โดยไม่เปลี่ยนระบบติดตามไอเท็ม

ไม่มีการรันชุดทดสอบที่ไม่เกี่ยวข้อง ไม่มีการเข้าถึง VPS ผู้เล่นจริง หรือข้อมูลจริง และไม่มีการ deploy ในงานนี้ การตรวจภาพด้วย browser fixture เตรียมไว้แล้ว แต่สภาพแวดล้อมนี้เปิด Chromium ไม่ได้ (`socket() failed: Operation not permitted`); จึงยังไม่ยืนยัน screenshot หรือทดสอบหน้าจอจริงบนโทรศัพท์

ผสานกับ main `c601b145` ซึ่งเพิ่ม paperdoll และย้าย HUD แล้ว โดยคงหน้าตัวละครและตำแหน่ง HUD ไว้ ใช้ `bindBagControls` ร่วมกัน และตัดโค้ดผูกปุ่มเก่าหลัง `return` ที่ไม่ถูกเรียกออกเพื่อไม่ให้มีงานช่างซ้ำสองชุด


## ช่องเลือกอุปกรณ์และกระเป๋ารุ่นล่าสุด (2026-11-05)

- แตะช่องอุปกรณ์ฝั่งซ้ายเพื่อเปิด dialog เลือกของ ใช้รูปแบบช่องเดียวกับกระเป๋า แสดงเฉพาะอาวุธหลักหรืออุปกรณ์ที่มี forge profile รวมของในกระเป๋าและช่องสวมจริงทั้ง 14 ตำแหน่ง
- ไม่ใช้เงื่อนไขชิ้นสละมากรองเป้าหมาย ของที่ผูก ใส่การ์ด มีออปชัน ขั้นเต็ม หรือเลเวล/ทองไม่ถึงยังเลือกดูได้ ปุ่มทำรายการเป็นผู้บอกข้อจำกัดตามสูตรเซิร์ฟเวอร์
- การแตะรายการตรวจ itemId และ stamp ปัจจุบันอีกครั้ง จึงไม่เลือกของแทนที่ในช่องเดิมโดยเงียบ ๆ การเปลี่ยนเป้าหมายล้างชิ้นสละ และไม่ส่งธุรกรรม
- Dialog ใช้ showModal, กัก Tab ภายใน, Escape/ยกเลิกคืนโฟกัสที่ช่อง และปิดเมื่อเปลี่ยนหน้า ห้อง หรือออกจาก LIVE
- หากคำขออ่านทองถูกปฏิเสธตอนตาย หน้าช่างจะอ่าน get_economy ใหม่ได้หลังมีชีวิต โดยจำกัดครั้งละอย่างน้อย 2 วินาทีต่อห้อง หยุดเมื่อได้ยอด และไม่ส่งซ้ำคำสั่งเปลี่ยนไอเท็ม
- ผสาน main eaea66e0 ซึ่งเปลี่ยนเป็นหน้าต่างข้อมูลไอเท็มกลางจอ โดยเก็บรูปแบบและสเตตัสใหม่ แต่ไม่เพิ่มแผงคราฟต์หรือตีบวกเก่าซ้ำ ทางลัดการ์ดเปิดหน้าต่างที่เลือกให้เห็นบนมือถือ พร้อมกักโฟกัสและปิดหน้าต่างเมื่อเปลี่ยนไปหน้าช่าง
- ชุดเฉพาะเพิ่มเติม: forge-picker-ui-test.cjs, artisan-wallet-ui-test.cjs, crafting-pages-ui-test.cjs และ item-display-ui-test.cjs การทดสอบ browser ของรุ่นนี้ต้องรายงานแยกตาม commit และผลจริง ไม่อนุมานจาก unit tests
