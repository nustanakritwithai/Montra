# MONTRA — แชทปาร์ตี้ แชทส่วนตัว และรายงานบัค

งานนี้เป็นสำเนาแยกจาก commit งานป่าแรก `729a610` มีแพตช์ `MONTRA-private-chat.patch` ที่ใช้กับ commit ดังกล่าว ต้องตรวจการเปลี่ยนแปลงล่าสุดของงานแผนที่ก่อนรวม และตรวจ `git apply --check <patch>` ไม่ควรใช้แพตช์ซ้ำกับสาขาที่รวมแล้ว ยังไม่มีการเผยแพร่หรือแก้เซิร์ฟเวอร์จริงจากงานชุดนี้

## การใช้งาน

เปิดแชทแล้วเลือกแท็บ ปาร์ตี้, ส่วนตัว หรือ รายงานบัค แชทปาร์ตี้ส่งเฉพาะสมาชิกปัจจุบันในห้องเดียวกัน แชทส่วนตัวเลือกผู้รับที่ออนไลน์ในห้องเดียวกัน ทั้งสองช่องเป็นข้อความชั่วคราว ไม่จัดเก็บประวัติและไม่รองรับส่งถึงผู้เล่นออฟไลน์ ข้อความรายงานบัคส่งเฉพาะเซิร์ฟเวอร์ ไม่ส่งเข้าช่องผู้เล่น เมื่อเขียนไฟล์สำเร็จจึงยืนยันกับผู้แจ้ง

รายงานประกอบด้วยรหัสรายงาน วันเวลา ชื่อตัวละคร แผนที่ พิกัด และข้อความ ไม่มี guest token หรือประวัติแชท แต่ผู้แจ้งอาจพิมพ์ข้อมูลส่วนตัวเองได้ ควรให้สิทธิ์เข้าถึงไฟล์เฉพาะผู้ดูแล จำกัด 200 อักขระและ 1 รายงานต่อ 30 วินาทีต่อ session รายงานอยู่ที่ `bug-reports/reports.jsonl` ภายใน `MONTRA_CHARACTER_DIR`; ถ้าใช้ตำแหน่งตั้งต้นของ VPS จะเป็น `C:\Montra\online-server\data\characters\bug-reports\reports.jsonl` เปิดดูเมื่อมีรายงานแล้วด้วย:

```powershell
Get-Content -LiteralPath 'C:\Montra\online-server\data\characters\bug-reports\reports.jsonl' -Encoding utf8 | ForEach-Object { $_ | ConvertFrom-Json } | Select-Object createdAt, name, mapId, text, id
```

หากตั้ง `MONTRA_CHARACTER_DIR` ไว้ที่อื่น ให้เปลี่ยน path ตามนั้น ไฟล์เป็น JSON Lines เพิ่มรายการต่อท้าย ไม่มีหน้าแอดมินในเกมหรือระบบจัดการสถานะบัค

## สถานะตรวจ

TypeScript strict และตัวเลือก build Windows ผ่าน กฎตรวจข้อความ 3 รายการผ่าน และทดสอบกับ Node/SQLite ในโฟลเดอร์แยกโดยใช้ผู้เล่น 3 คน: สมาชิกปาร์ตี้เห็นเฉพาะข้อความปาร์ตี้ ผู้รับส่วนตัวและผู้ส่งเห็นข้อความ คนนอกไม่เห็น รายงานถูกบันทึกจริงและไม่ส่งถึงผู้เล่นอื่น ตรวจ rate limit และการปลอมชื่อใน payload แล้ว Syntax ของ JavaScript และ PowerShell installer ผ่าน ยังไม่ได้ทดสอบหน้าจอในเบราว์เซอร์จริงหรือ GitHub Actions

ไฟล์ installer ดาวน์โหลดจาก GitHub main จึงต้องรวม source ให้ครบและเผยแพร่ client กับ server รุ่นที่ตรงกันก่อนนำไปใช้ ค่า `extendedChatAvailable` ใช้บอก client ว่า server รองรับช่องใหม่ ไม่ใช่คำสั่งให้เปิด LIVE
