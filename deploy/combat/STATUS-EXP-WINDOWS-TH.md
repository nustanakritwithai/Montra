# MONTRA V0.3.0 — Status และ EXP

สเตตัสคำนวณบนเซิร์ฟเวอร์ตามโมเดล Hybrid: Lv.1 มี HP 240, ATK 20, DEF 30, Magic ATK 15, Magic DEF 20 และ Stamina 100; ค่าหลักเติบโตด้วย `1 + (level - 1) / 15` ค่าป้องกันนำไปลดดาเมจแบบ diminishing returns Stamina ใช้ 50 ต่อการพุ่งและฟื้นตามสถานะต่อสู้

EXP ที่ต้องใช้ไปเลเวลถัดไปคำนวณจาก `50 × เลเวลปัจจุบัน² + 100` เช่น Lv.1 ใช้ 150 และ Lv.2 ใช้ 300 เลเวลสูงสุด 100 ผี Lv.1 ให้ 100 EXP ที่เลเวลเท่ากัน ลด 5% ของค่าพื้นฐานต่อเลเวลที่ผู้เล่นสูงกว่าผี และเป็น 0 ตั้งแต่ Lv.21 รางวัลเป็นของตัวละครถาวรที่ลงดาเมจสุดท้าย รวมการโจมตีของวิญญาณเจ้าของ และบันทึกก่อนแจ้งสำเร็จ PvP ไม่ให้ EXP สเตตัสเพิ่มอัตโนมัติ ไม่มีการแจกแต้ม การลดทอนรางวัลนี้หมายความว่าต้องเพิ่มมอนสเตอร์เลเวลสูงหรือกิจกรรมอื่นก่อนจึงจะเก็บ EXP ต่อได้หลัง Lv.20

Soft Cap ATK/เวท 2,000 และ DEF/ป้องกันเวท 500 โดยส่วนที่เกินมีผล 50%; ออกจากสถานะต่อสู้หลังไม่มีการต่อสู้ 5 วินาที ค่าเหล่านี้เลือกเป็นค่าเริ่มต้นสำหรับทดลองและต้องปรับจากการเล่นจริง

เซฟเดิมคง Character ID, Guest ID, ช่อง 1–3, HP ปัจจุบัน, อาวุธ, ไอเท็ม และ Map ID โดยไม่มีการแจกไอเท็มซ้ำ เซฟทดลองจากร่างก่อนที่มีแต้มลงทุนแล้วจะยังเก็บโบนัสเดิม แต่แจกเพิ่มไม่ได้

## ติดตั้ง

หลัง PR ผ่าน CI และ merge แล้ว ให้เจ้าของ VPS ตรวจ `MONTRA_CHARACTER_DIR` ว่าเป็นเซฟที่ process MONTRA ใช้จริง สำรองเซฟทุกช่องแยกไว้และตรวจว่าอ่านได้ เลือกช่วงไม่มีผู้เล่นทำธุรกรรม แล้วรัน `deploy/combat/install-windows.ps1` ตัวติดตั้งสำรอง source, build และเซฟก่อน build และไม่รีสตาร์ต Node อัตโนมัติ ตรวจ `MONTRA STATUS AND EXP BUILD PASSED.` ก่อนเปิดเฉพาะ MONTRA ด้วยโฟลเดอร์เซฟเดิม ห้ามรัน integration tests กับ LIVE

## Rollback

**ห้ามนำ build ก่อน V0.3.0 มาเขียนเซฟที่ได้รับสเตตัสแล้ว** เพราะโค้ดเก่าอาจละทิ้งข้อมูลแต้มและ Stamina หากจำเป็นต้องย้อน ให้หยุดเฉพาะ MONTRA สำรองเซฟล่าสุดทั้งหมดแยกอีกชุด แล้ววางแผนแปลงข้อมูลก่อนเปิด build เก่าหรือใช้รุ่นแก้ไขที่ยังอ่านฟิลด์ใหม่ได้ ห้ามเขียนทับเซฟล่าสุดด้วย backup เก่าโดยไม่ตรวจความคืบหน้า
