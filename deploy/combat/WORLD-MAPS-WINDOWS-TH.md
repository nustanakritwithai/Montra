# MONTRA V0.2.8 — ติดตั้งและกู้คืนบน Windows VPS

เอกสารนี้ใช้เมื่อโค้ด V0.2.8 ผ่าน CI, รีวิว และ merge เข้า main แล้วเท่านั้น GitHub Pages กับเซิร์ฟเวอร์เป็นคนละส่วน การอัปเดต Pages ไม่ได้อัปเดต Node บน VPS

## ก่อนติดตั้ง

1. ให้เจ้าของ VPS ตรวจว่ามีพื้นที่ว่างเพียงพอสำหรับสำเนา `C:\Montra\online-server\build`, source และโฟลเดอร์ `MONTRA_CHARACTER_DIR` ทั้งหมด รวมถึง backup แยกนอก VPS ตรวจสำเนาให้เปิดอ่านได้ โดยรักษาความลับของเซฟ
2. ตรวจ path ของ `MONTRA_CHARACTER_DIR` ที่ process MONTRA ใช้จริง และตรวจว่า backup ครบทุกไฟล์ character ทั้งสามช่อง โดยไม่เปลี่ยนชื่อหรือลบเซฟ
3. ติดตั้งเมื่อไม่มีผู้เล่นทำธุรกรรม และตรวจ PR/commit กับ CI ที่ผ่านก่อน ไม่ทดสอบ integration บน LIVE หรือใช้โฟลเดอร์เซฟจริง

## Build แบบไม่รีสตาร์ต

ดาวน์โหลด `deploy/combat/install-windows.ps1` จาก commit ที่ผ่านการตรวจแล้วไปยังเครื่อง VPS ตรวจเนื้อหาไฟล์ แล้วรัน PowerShell ในฐานะผู้ดูแลจากไฟล์ที่ดาวน์โหลด:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Montra\deploy\install-windows.ps1
```

ตัวติดตั้งดาวน์โหลด source จาก `main`, สำรอง source, build และ character data ก่อนแก้ไฟล์ จากนั้น build และคืน source/build หาก build ล้มเหลว ตัวติดตั้งไม่สั่งหยุดหรือรีสตาร์ต Node, Caddy หรือเกมอื่น ตรวจ path backup ที่แสดงและผล `MONTRA WORLD MAP BUILD PASSED.` ก่อนดำเนินการต่อ เจ้าของ VPS ต้องระบุ process ของ MONTRA ให้แน่ใจ และจัดการ restart เฉพาะ process นั้นด้วยวิธีที่ตนใช้ ไม่ใช้คำสั่งปิด Node ทั้งเครื่อง

## หลังติดตั้ง

ทดสอบกับเซิร์ฟเวอร์ทดสอบแยก พอร์ตแยก และ `MONTRA_CHARACTER_DIR` ชั่วคราวที่ชื่อเริ่มด้วย `montra-world-test-` เท่านั้น ตรวจวาร์ปไป–กลับ, รีสตาร์ต Node ทดสอบ, ทั้งสามช่อง, จำนวนยาและอาวุธ ก่อนเปิดให้ผู้เล่น LIVE ตรวจ Pages และ server version ให้ตรงกัน

## Rollback และข้อมูลเซฟ

ห้ามนำ build ก่อน V0.2.8 กลับมาเขียนเซฟที่มี `mapId`: โค้ดเก่าอาจลบฟิลด์นี้หรืออ่านตำแหน่งป่าผิดแผนที่ หากต้องย้อนไป build เก่า ให้หยุดเฉพาะ MONTRA, เก็บสำเนาเซฟปัจจุบันแบบไม่แก้ไข และวางแผนกู้คืน/แปลงข้อมูลโดยตรวจแยกทุกช่องก่อนเปิดเขียน ห้ามทับเซฟปัจจุบันด้วย backup เก่าโดยไม่เปรียบเทียบ เพราะจะทำให้ความคืบหน้าหลัง backup สูญหาย การแก้ไปข้างหน้าด้วย build ที่เข้าใจ `mapId` ปลอดภัยกว่า

ใน V0.2.8 ผู้เล่นยังอยู่ Colyseus room เดียวกัน ระบบแยกการจำลองและแสดงผลตาม Map ID แต่ข้อมูลผู้เล่นยังถูกส่งใน room เดียวกัน ไม่ใช่การแยก server หรือการปกปิดข้อมูลระหว่างโซน
