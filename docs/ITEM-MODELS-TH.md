## 2. สาเหตุ

1. **เครื่องประดับบอสไม่มีเลขท้าย ID** — `gearLook()` ใช้ regex `^(family)_(\d+)$` ไอเท็ม `acc_boss_<แผนที่>` จึงไม่ถูกส่งไปหน้าเว็บเลย (16 ชิ้น)
2. **ชิ้นสายอาชีพส่ง family ผิด** — ID `arm_field_seer_37` ถูกส่งเป็น `arm_field_seer:37` ทุกช่อง หน้าเว็บตีความเป็นชุดเกราะ ช่องมือรอง สร้อย ต่างหู แหวน จึงไม่มีตัวสร้าง (174 ชิ้น)
3. **ระดับภาพชุด field ผิด** — ตัวเลขท้ายคือเลเวลไอเท็ม (2–99) ไม่ใช่ระดับชุด ตัวสร้างตัดที่ระดับ 9 ทำให้ชุดเลเวล 9 แสดงเป็นเกราะดำมีแสง (ระดับสูงสุด)
4. **ต่างหูข้างเดียวแสดงสองข้าง** — ตัวสร้างต่างหูวาดทั้งซ้ายขวาทุกครั้ง

## 3. สิ่งที่แก้

**เซิร์ฟเวอร์** (`deploy/combat/ItemRules.ts`)
- `gearLookPart(id)`: ใช้ `family` และ `level` จากแคตตาล็อก → `family:ระดับชุด` (ระดับคำนวณจาก `OUTFIT_LEVELS` แบบเดียวกับไอเท็มปกติ)
- รูปแบบข้อความ `slot=family:tier;…` เหมือนเดิม ไม่เปลี่ยน schema, ID, สเตตัส หรือไฟล์เซฟ
- ไอเท็มปกติ 408 ชิ้นได้ค่าเดิมทุกตัว (ตรวจเทียบก่อน/หลังครบ) เปลี่ยนเฉพาะ field 516 และบอส 16

**หน้าเว็บ** (`src/client/render/021-character-models.js`)
- เลือกตัวสร้างตามช่อง: แหวน → ringBuilder, ต่างหู → earringBuilder (ข้างเดียว), สร้อย → accessoryBuilder, มือรอง → OFFHAND_BUILDERS
- `normalizeGearLook()`: รองรับข้อมูลแบบเก่าจากเซิร์ฟเวอร์ที่ยังไม่อัปเดต (`arm_field_<อาชีพ>:<เลเวล>`) แปลงเป็นชิ้นจริงของชุดอาชีพและระดับชุดที่ถูกต้อง
- เครื่องประดับบอส: อัญมณีเรืองแสง ต่างหูบอสมีจี้ห้อยเพิ่ม

**ผลระหว่างช่วงเปลี่ยนผ่าน**: หน้าเว็บใหม่ + เซิร์ฟเวอร์เก่า → ชิ้นสายอาชีพ 174 ชิ้นแสดงได้ทันที เหลือบอส 16 ชิ้นที่ต้องรออัปเดตเซิร์ฟเวอร์

## 6. แผนสร้างโมเดลเฉพาะชิ้น

ลำดับตามสิ่งที่ผู้เล่นเห็นบ่อยที่สุดก่อน
1. **อาวุธ 6 อาชีพ 3 ช่วงระดับ** (ฝึกหัด / กลาง ≥ เลเวล 45 / สูง ≥ 85) = 18 โมเดล แทนที่ 6 แบบปัจจุบัน
   - **ขั้นแรกทำแล้ว (procedural)**: ระดับ 6–8 เพิ่มปลอกทองและอัญมณี ระดับ 9–10 เพิ่มคมเรืองแสงตามแนวใบ/วงแสงที่หัวไม้เท้า และพู่แดง
     สร้างเมื่อถือจริงเท่านั้น รวมเป็น mesh เดียวต่อช่วงระดับ (< 300 สามเหลี่ยม) ใช้ `equippedWeaponId` ที่เซิร์ฟเวอร์ส่งอยู่แล้ว ไม่ต้องแก้เซิร์ฟเวอร์
     ยังไม่ครอบคลุมมวยไทย (ผ้าพันมือไม่มีโมเดลอาวุธ) และยังไม่ใช่โมเดล GLB เฉพาะชิ้น
2. **ชุดอกและหมวก 4 น้ำหนัก 3 ช่วงระดับ** = 24 ชิ้น (อก/หัว/บ่า เห็นชัดที่สุดจากกล้องมุมสูง)
3. **มือรอง 6 อาชีพ 2 ช่วงระดับ** = 12 ชิ้น
4. **เครื่องประดับบอส 16 ชิ้น** แยกทรงตามธีมแผนที่ (เป็นรางวัลหายาก ผู้เล่นอยากโชว์)
5. ลดสามเหลี่ยมบ่าเกราะ (7,024 → ≤1,200) ก่อนเริ่มข้อ 2

**งบต่อชิ้น (มือถือ)**
| ประเภท | สามเหลี่ยม | Texture | ไฟล์ GLB (ไม่รวม texture ที่ใช้ร่วม) |
|---|---:|---|---:|
| อาวุธ | 800–1,500 (LOD1 ≤ 400) | atlas ร่วม 512² KTX2/WebP | ≤ 60 KB |
| ชุดอก/หัว/บ่า | 600–1,200 ต่อชิ้น | atlas ร่วมต่อน้ำหนัก 512² | ≤ 50 KB |
| มือรอง | 500–1,000 | atlas ร่วม | ≤ 40 KB |
| เครื่องประดับ | 150–400 | ใช้ material สีเดิม | ≤ 15 KB |
| รวมตัวละครแต่งเต็ม | ≤ 20,000 (ปัจจุบันเกราะหนักเต็มชุด ~19,000) | | |

**สไตล์มนตรา**: ลวดลายกนก/ยันต์ ทอง-ชาด-ดำ ตามระดับเดิม (ทองเริ่ม 3, ชาด 5, เรือง 7) ให้ผู้เล่นเดาระดับจากรูปร่างได้แม้ไม่เห็นสี

**วิธีทดสอบก่อนนำเข้า**
1. ตรวจไฟล์: glTF validator, จำนวนสามเหลี่ยม/วัสดุ/ขนาดตามงบ, กระดูกและจุดยึด (`Socket_Hand_Weapon_R/L`, ระยะจาก GEAR_REST)
2. เทสต์อัตโนมัติ: เพิ่มเกณฑ์งบในสคริปต์ geometry เดิม (ทุก family สร้างได้, ไม่เกินงบ)
3. ภาพเทียบอัตโนมัติด้วยระบบถ่ายเฟรมที่ใช้ในงานนี้: ท่ายืน/เดิน/โจมตี 4 มุม เทียบกับภาพอ้างอิง
4. ประสิทธิภาพ: S22 emulation (CPU/4) ฉากหมู่บ้าน 10 ตัวละครแต่งเต็ม เทียบ JS/frame และหน่วยความจำก่อน/หลัง แล้วยืนยันบนเครื่องจริง
5. โหลดแบบ lazy ตามช่วงระดับ พร้อมรูปทรง procedural เดิมเป็น fallback ระหว่างโหลด

## 7. การเผยแพร่ฝั่งเซิร์ฟเวอร์ (ยังไม่ได้ทำ)

ส่วนหน้าเว็บปลอดภัยที่จะเผยแพร่ก่อน (รองรับเซิร์ฟเวอร์เก่า) ส่วนเซิร์ฟเวอร์ (`ItemRules.ts`) ต้องทำตามนี้
1. **Staging**: ติดตั้ง commit ที่ผ่าน CI ลงโฟลเดอร์แยก ใช้สำเนาข้อมูลตัวละคร ไม่ใช่ข้อมูลจริง รัน `gear-look-integration.mjs` ชี้ไปที่ staging
2. **สำรองข้อมูล**: หยุด MONTRA เฉพาะพอร์ต 4108, คัดลอก `MONTRA_CHARACTER_DIR` ทั้งโฟลเดอร์รวม SQLite + WAL/SHM, ตรวจ SHA-256
3. **ตรวจการกู้คืน**: กู้สำเนาลงโฟลเดอร์ชั่วคราว เปิดเซิร์ฟเวอร์ staging กับสำเนานั้น เข้าเกมได้และอุปกรณ์ครบ
4. **ติดตั้งจริง**: `install-windows.ps1 -Revision <SHA>` (ตัวติดตั้งสำรอง source/build ให้อัตโนมัติ)
5. **Rollback**: ถ้ามีปัญหา หยุดพอร์ต 4108 แล้วคืน source/build จาก `backup-before-*` ที่ตัวติดตั้งสร้าง — ไม่ต้องคืนข้อมูลผู้เล่น เพราะงานนี้ไม่เปลี่ยนรูปแบบเซฟ
